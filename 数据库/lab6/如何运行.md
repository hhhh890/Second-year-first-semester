在Linux环境里执行，进入仓库根目录：

cd "XXXXX/bonus lab/Bonus_Lab_About_TP_Performance_Optimization-main"

一、先编译

如果是第一次跑，先执行：

cmake -B build -S .
cmake --build build --target rmdb tpcc_loader tpcc_driver -j$(nproc)

如果还想跑 B+ 树 gtest，也一起编译：

cmake --build build --target b_plus_tree_insert_test b_plus_tree_delete_test b_plus_tree_concurrent_test -j$(nproc)

二、跑 B+ 树正确性测试

./build/bin/b_plus_tree_insert_test
./build/bin/b_plus_tree_delete_test
./build/bin/b_plus_tree_concurrent_test

预期结果：

insert test：2/2 passed

delete test：3/3 passed

concurrent test：2/2 passed

三、准备 TPC-C 数据库

跑 scale=10 的测试前，先准备 golden 数据库：

bash scripts/01_setup.sh --only=10 --rebuild

这个会重新编译、建库、灌入 TPC-C 数据，并保存一个 golden_s10，之后每次性能测试会从 golden 库快速恢复。

如果只是想补 golden，不重新编译，可以用：

bash scripts/01_setup.sh --only=10 --skip-build

四、跑主要性能测试

推荐同学先跑这个，时间比较合适：

bash scripts/02_run_s10_t4_d60.sh

配置是：

scale=10

threads=4

duration=60s

脚本会自动做这些事：

检查二进制和 golden 库。

恢复 tpcc_db。

启动 rmdb server。

运行 tpcc_driver。

结束后关闭 server。

输出 tpmC、TPS、abort、latency。

五、看结果

脚本结束后，终端会出现类似结果：

duration

committed

aborted

TPS

tpmC

latency p50/p95/p99

也可以看日志文件：

build/dbroot/driver_s10_t4_d60.log

build/dbroot/server_s10_t4_d60.log

六、如果想跑长时间测试

可以跑：

bash scripts/03_run_s1_t4_d300.sh

这个是：

scale=1

threads=4

duration=300s

时间更长，适合报告里的长压结果，不建议每次改代码都跑。

如果缺少 golden_s1，它会先准备数据，耗时会更久。
